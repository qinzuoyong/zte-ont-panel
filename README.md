# 中兴光猫控制面板（Telnet 图形界面）

针对**已开启 Telnet 的中兴光猫**的专用控制面板。
点按钮执行命令，不依赖 PuTTY/MobaXterm 等通用终端，单 exe 双击即用。

**连上设备后会自动识别机型**，并加载该机型对应的命令清单。

> **已实测机型**
>
> | 机型 | 状态 |
> |---|---|
> | ZXHN F650（2017，GPON，SoC ZX279127） | ✅ 已连真机验证 |
> | G7615 / G7615V2 / F7607P 等万兆系列 | ⚠️ 按社区资料编写，**未连真机验证** |
>
> 其他机型会按「通用最小集」工作，并自动隐藏已知不支持的命令。

## 直接使用

从 [GitHub Releases](https://github.com/qinzuoyong/zte-ont-panel/releases/latest) 下载
`中兴光猫控制面板-v1.1.0.exe`，双击即可，无需安装运行库。

> 仓库只放源码与文档，exe 作为发行版附件发布，不进入 git 历史。
> 也可以按「重新编译」一节的步骤自行构建。

> **首次运行会被 SmartScreen 拦**：这是未签名的新文件，Windows 对它没有信誉记录。
> 点「更多信息」→「仍要运行」即可；或右键文件 → 属性 → 勾选底部「解除锁定」→ 确定。

连接参数（默认值如下，程序会记住上次用的地址/账号）：

| 项 | 默认值 |
|---|---|
| 地址 | `192.168.1.1` |
| 端口 | `23` |
| 账号 | `root` |
| 密码 | **不保存，每次输入**（密码框右侧「常用 ▾」可一键填入公开默认口令） |

> 密码不落盘是刻意的安全取舍，理由见「P2-4」一节。
> 若你的环境不同（IP/账号），在界面顶部连接栏修改后再点「连接」。

**关于默认密码**：密码框右侧有「常用 ▾」菜单，里面是**公开可检索的出厂默认口令**，
点一条就填进输入框（账号框为空时会一并填上账号，非空则不动）。它只填、不试、不连、不落盘。

| 账号 / 口令 | 适用 | 出处 |
|---|---|---|
| `root` / `root` | F650 天翼网关 3.0 换掉 telnetd 之后 | 宽带技术网开 telnet 教程、恩山免拆机教程（两条独立来源） |
| `root` / `Zte521` | 中兴固件自带 telnet | 两个独立的 zteOnu 仓库 README |
| `telecomadmin` / `nE7jA%5m` | 电信超管 / factory 模式 | zteOnu 默认认证参数 + 多篇汇总 |
| `CUAdmin` / `CUAdmin` | 联通超管（Web 管理页） | 同上 |

> 这些是厂商出厂值，本来就印在别人的帖子和开源工具里，写进源码不泄露任何东西。
> 项目红线「密码不落盘」针对的是**你自己改过的密码**，两件事不能混为一谈。
> 清单里没有 `admin/admin` 这类论坛口口相传但查不到出处的组合 —— 收进来就是拿你的设备去试。

**关于端口（重要）**：本程序是 Telnet 客户端，端口固定填 **23**（Telnet 标准端口）。
你可能听说的 **8080** 是电信版光猫的 **Web 管理端口**（浏览器访问 `http://192.168.1.1:8080`，用 telecomadmin 登录），
那是网页服务，不是 Telnet；把本程序端口填成 8080 会连到网页而无法登录命令行。

## 功能

界面是「顶栏 / 侧栏 / 中央日志 / 底部命令条 / 回读校验卡片」五区结构，
设计令牌（间距刻度、字号、配色）集中定义在 `src/theme.rs`，
依据见 [`docs/设计规范.md`](docs/设计规范.md)。

- **顶栏（55px）**：品牌 + 机型徽标 + 状态灯 + 连接胶囊；右侧是地址/端口/账号/密码与连接按钮，密码可切换明文
- **侧栏（默认 302px，可拖拽 187–489）**：搜索框（`Ctrl+K`）过滤全部操作；分组标题可折叠（自绘三角）；
  每个操作是整行可点按钮，**危险操作左侧有红色竖条 + 行尾「危险」字样**（颜色之外还有形状线索）；
  底部「表结构查询」收进折叠区
- **中央日志**：等宽 13px、行高 21，**按语义逐行着色**（命令回显=强调色、✅ 已确认=绿、❌ 失败=红、
  ⚠ 无法确认=黄、分节标题=主文字、分隔线=弱文字）；工具条有行数、自动滚动开关、清空、复制
- **右下：回读校验卡片**：标题行带三态计数（✅ / ❌ / ⚠ + 数字），下面是可滚动明细
- **底部命令条**：`>` 提示符风格输入框，`Ctrl+Enter` 发送
- **危险确认与参数表单**：居中模态 + 遮罩，危险操作**必须二次确认**，不可跳过

### 写后回读校验（重要）

中兴的 `sendcmd 1 DB set` 在**字段名或行号写错时不会报任何错**：
命令照常返回、无任何输出、退出码正常，而配置根本没写进去。
界面上原本会显示「----- 完成 -----」，用户被误导为修改成功。

现在每条写命令执行后会**立刻回读该表并比对目标字段**，结果显示在右下角面板：

| 标记 | 含义 |
|---|---|
| ✅ | 回读确认已生效 |
| ❌ | 未写入 / 值与预期不符 / 回读失败无法确认 |

判定规则：

1. 优先按「行号 + 字段名」精确比对
2. 行号对不上时退化为「任意行找同名字段」——设备重建行、行号漂移时，值对就算生效
3. 值比对忽略首尾空白与大小写（设备可能归一化 MAC 大小写、裁掉 SSID 空格）

批量操作结束时日志里还会有一条汇总，例如
`----- 回读校验：6/8 条写命令已确认生效 -----`。
**看到 ❌ 或「未通过回读校验」，说明配置可能没真正写入**，
请到「表结构查询 → 读整表」里核对真实字段名，不要直接开始用。

> 注意：`sendcmd 1 DB save`、`delr`、`reboot` 这类命令没有单字段可回读，
> 不参与校验（这是设计如此，不是漏了）。

### 表结构查询

字段名不确定时**不要猜**：先用左侧「列出全部表名」（`sendcmd 1 DB all`）
或「读整表」（`sendcmd 1 DB p <表名>`）把设备真实表打出来看。
社区教程里的字段名在不同固件/省份版本间会有差异，
以你这台设备的实际回显为准。

### 字段名确认情况（按真机回显）

原先这里登记的是「字段名待确认、故意不猜」的项。
连真机（F650）探查后，大部分已确认并写进 `命令预设_f650.txt`：

| 原待确认项 | 真机结论 |
|---|---|
| `WLANCfg` 的 SSID / 隐藏开关 / 启用开关 | ✅ 确认：`ESSID` / `ESSIDHideEnable` / `Enable` |
| WiFi 密码字段 | ✅ 确认在 **`WLANPSK`** 表（不在 `WLANCfg`），字段名 `KeyPassphrase` |
| 无线射频参数 | ✅ 确认在 `WLANBase` 表（信道 `Channel`、模式 `11nMode` 等） |
| `WANC` 的 VLAN ID 字段名 | ⏳ **仍未确认** —— 本机未使用 WANC 相关功能，无实测数据 |
| `WANC` 新建连接的完整字段集 | ⏳ **仍未确认** —— 同上，建议直接用 Web 界面建 |

> `WANC` 两项需要你实际用到桥接/VLAN 时，
> 用「读整表 → `WANC`」查到真实字段名再自行加进预设文件。
> 在那之前不放按钮，避免点了静默失败。

### 敏感字段的回读遮蔽（实测发现）

**F650 会对 `WLANPSK.KeyPassphrase` 的回读做遮蔽**：写入前后读回来都是 `******`。

这意味着 WiFi 密码**无法用回读校验确认**。程序的处理方式是三档结论：

| 标记 | 含义 |
|---|---|
| ✅ | 回读确认已生效 |
| ❌ | 未生效（值不符 / 字段不存在 / 需回读的表读不到） |
| ⚠ | **设备遮蔽了该字段，无法确认**（已知：WiFi 密码） |

⚠ 既不是成功也不是失败。报成功是假保证，报失败是假警报 ——
所以如实显示「无法确认」，请你手动用手机连一次验证。

### 换机流程

见上文「P2-4：连接参数记忆 + 换机向导」——
界面左侧「换机向导（按顺序执行）」分组已按 ①～⑩ 编号排列，照着点即可。

> `setmac` 命令**不在回读校验覆盖范围内**（P0 的校验只认 `sendcmd 1 DB set`，
> 因为 `setmac` 写的是系统参数区而非配置表）。所以**改 SN/MAC 后请务必用
> 换机向导的 ① / 「PON 认证与设备标识 → 查看全部系统参数」人工复核一次**。
> 这也是为什么向导把 ①②③ 的只读记录步骤排在所有写入之前。

### 关于 SmartScreen 警告（已实测确认，不要再折腾）

首次双击会弹蓝色窗口「Windows 已保护你的电脑」。**这是必然的，属正常现象**，
点「**更多信息 → 仍要运行**」即可；同一个文件点过一次后本机不再询问，
**只要不重新编译就不用再点**。

> ⚠️ **不要试图用自签名证书消除它** —— 本项目已经实测走过一遍，结论是无效。

实测记录（2026-10-13）：

1. 用 OpenSSL 生成两级证书（自建 CA + 代码签名叶子证书），
   用 `osslsigncode` 签名并加 DigiCert 时间戳，把 CA 导入
   「受信任的根证书颁发机构」。
2. 结果：`Get-AuthenticodeSignature` 返回 `Valid`，exe 属性页「数字签名」页正常。
3. **但 SmartScreen 照样拦截**。窗口里甚至已经正确显示出发布者
   （`发行者: CN, yong, yong Code Signing`），仍然拦。

原因：**SmartScreen 只信任微软信誉库里由商业 CA 签发的证书**，
自签名证书不在该库中，对它而言等同于未签名。它能读出签名者是谁，
但不会因此放行。

结论：

- 免费方案里，**只有「点仍要运行」和「关闭 SmartScreen」两条路**
- 唯一能彻底消除警告的是 **EV 代码签名证书**（一年几百到几千元），自用不值得
- 自签名证书的唯一作用是「文件被篡改可被发现」+「属性页有发布者」，与 SmartScreen 无关

> 自签名 CA 已从本机证书库移除（避免本机长期信任一把自用私钥）。
> 证书与签名脚本仍保留在 `D:\rust\codesign\`（未放进本项目目录）。

### 三个容易踩的坑（都已处理，改配置时别退回去）

1. **必须用 glow 后端，不能用默认的 wgpu。**
   `Cargo.toml` 里写的是 `default-features = false, features = ["glow", ...]`。
   本机实测 wgpu 的默认初始化路径会在启动时耗尽主线程栈，
   症状是一启动就 `thread 'main' has overflowed its stack`（退出码 0xC0000005）。
2. **主线程栈通过 `build.rs` 加到 16MB。**
   Windows 默认只给主线程 1MB。不能改成「把 GUI 放到子线程跑」——
   winit 在 Windows 上明确拒绝在非主线程创建事件循环。
3. **版本资源由 `build.rs` 直接手写，不走 `windres`。**
   本机 mingw 是精简版，没有 `gcc`，而 `windres` 预处理 `.rc` 必须调用 `gcc`，
   直接报 `preprocessing failed`。改用系统自带 `more.com` 当预处理器也不行：
   它会把 LF 扩成 CRLF 改坏文本，且 `windres` 无法把中文正确写进资源
   （ASCII 能进，中文和 Latin-1 都丢）。所以 `build.rs` 自己拼 PE 资源树
   （三层 `IMAGE_RESOURCE_DIRECTORY` + `VS_VERSIONINFO`），再手工包成 COFF
   目标文件交给链接器。关键细节都写在 `build.rs` 注释里，改之前请先读一遍：
   - 第 2 层用数字 ID `1`（不是命名字符串 `VS_VERSION_INFO`）
   - 目录条目里的偏移**不能**加 COFF 重定位（最高位是「指向子目录」标志位），
     只有数据条目的 `OffsetToData` 需要重定位（`ADDR32NB`）
   - `wValueLength` 对字符串是「字符数含结尾 `\0`」；补齐一律按**绝对位置**算 4 字节边界
   - 资源语言用 `0x0804`，须与目标机系统 UI 语言一致

### P6：敏感字段遮蔽处理 + WiFi 密码按钮（2026-10-14）

**背景**：此前把「F650 的 WiFi 密码」列为无法实现的功能，
理由是 `WLANPSK.KeyPassphrase` 回读永远是 `******`。

**实测澄清**：在真机上做了一次受控写入实验（写入 `TestPass2026` 后回读），
确认设备**无论写入前后都返回 `******`** —— 这是设备的保护行为，不是写入失败。
原先的结论「不能做」其实只对了一半：**写入是可行的，只是无法自动校验**。

**改动**：把回读校验从两档（成功/失败）改成三档：

| 标记 | 含义 |
|---|---|
| ✅ | 回读确认已生效 |
| ❌ | 未生效 |
| ⚠ | **设备遮蔽了该字段，无法确认** |

关键判断：遮蔽与失败是**完全不同的两件事**。若并成一档，
用户会看到一个永远红色的 ❌，而事实上写入成功了 —— 那是假警报；
反之报成功则是假保证。只能如实说「不知道」。

批量操作的汇总也相应区分，不再把遮蔽计入「未通过校验」的数量。

**新增 4 个 WiFi 密码按钮**（`命令预设_f650.txt`）：
分别对应 `WLANPSK` 表的第 0～3 行，带密码强度校验（至少 8 位）。
风险说明里明确写了「本机型会遮蔽回读，界面会标 ⚠，请手动确认」。

**验证**：`is_masked` 与 `Verdict` 共 5 条新测试，覆盖
遮蔽识别、遮蔽不判失败、遮蔽与已确认的区分、真实失败仍判失败。
测试总数据此增至 164。

### P5：运行数据收进 `数据/` 子目录（2026-10-14）

**起因**：根目录被运行数据弄乱了 —— 每次运行都往里塞 `连接设置.txt`、
`配置备份/`、`运行日志/`，和交付物混在一起。

**改动**：新增 `src/paths.rs` 作为目录布局的**唯一出处**。
原先路径计算散在 4 个模块里（`backup.rs` / `settings.rs` / `presets.rs` / `main.rs`），
改结构要同时改四处、容易漏；现在只有一处知道目录长什么样。

新布局：

```
│  ├─ 连接设置.txt        #    地址/端口/账号（不含密码）
│  ├─ 配置备份/           #    写操作前自动存档的原值
│  └─ 运行日志/           #    每次运行的完整日志（保留最近 20 个）
```

**预设文件刻意留在根目录**：那是用户会主动编辑的东西，埋深了不好找。

**自动迁移旧布局**：升级时若发现根目录里已有 `连接设置.txt` / `配置备份/` /
`运行日志/`，程序会**一次性搬进 `数据/`**，避免用户以为「设置丢了、日志没了」。

迁移规则（保守）：
- 只在**目标不存在**时搬 —— 绝不覆盖新数据
- 用 `rename` 整目录搬（同盘原子操作）
- 搬迁前先做，**排在读取设置之前** —— 否则先读就读不到老设置
- 搬迁结果写进启动日志，用户能看见发生了什么

**验证**：在临时目录里模拟老布局（`连接设置.txt` 内容为 `10.9.9.9`/`admin`），
启动新 exe 后确认：三个条目全部搬入 `数据/`、设置值原样保留、
旧日志与旧备份都在、根目录只剩 exe + 预设 + `数据/`。

### P3：通用化 + 机型自适应（2026-10-14）

**起因**：连真机后发现，被当作 G7615 调试的设备实际是 **ZXHN F650**（2017 年 GPON 光猫）。
两者相差数代，表名、字段名、可用命令差异很大。实测对比：

| 命令 | G7615（2023 万兆） | F650（2017 GPON） |
|---|---|---|
| `upgradetest getver` | 返回版本号 | `function not found!!!` |
| `cat /proc/capability/boardinfo` | 返回硬件信息 | 文件不存在 |
| `sendcmd 1 DB p WLANPSK` | 表不存在 | 返回 4 行 PSK |
| WiFi 加密字段 | 新命名 | `11iAuthMode` 等老命名 |

按单一机型硬编码，换台设备就有一堆按钮点了报错。所以改成**自动识别机型**。

**1. 机型识别（`src/model.rs`）**

连上设备后自动跑两条**只读**探测命令，按可靠性排序判定：

1. `cat /proc/cpuinfo` 的 `Hardware:` 行 —— SoC 型号与机型强绑定，最可靠
2. `DevInfo` 的 `ModelName`
3. 版本号年份兜底

判定结果会显示在左侧栏，例如「机型：F650 系列（GPON）」。

**2. 按机型加载清单**

查找顺序（exe 同目录）：

1. `命令预设_<机型>.txt` —— 机型专用清单
2. `命令预设.txt` —— 通用清单
3. 内置清单

机型专用清单优先，因为它按该机型的**真实回显**核对过。

**3. 自动隐藏不支持的命令**

识别出机型后，该机型已知不可用的命令会被剔除；
整个操作被剔光的，按钮直接不显示（避免留一个点了什么都不做的空按钮）。
界面上会提示「已隐藏 N 条本机型不支持的命令」，让你知道不是程序坏了。

**4. 新增 F650 专用清单**

`命令预设_f650.txt`，命令全部基于**真机回显**核对，包含：

- WiFi 配置（`WLANCfg` 的 SSID/隐藏/开关、`WLANBase` 射频参数、`WLANPSK` 密码表）
- 账号与权限（`DevAuthInfo` 的 6 行结构，实测确认）
- 限制解除、ITMS、TR069、Telnet 固化

**验证**：连真机跑探测，独立复算出 `F650Series`，与 Rust 侧单测结论一致。
确认被剔除的两条命令在真机上确实不可用（`function not found` / 文件不存在）。

### P2-4：连接参数记忆 + 换机向导（2026-10-14）

**1. 记住地址/端口/账号，但绝不记密码**

连接成功后自动把地址、端口、账号存到 `连接设置.txt`，下次启动自动回填。

**密码不落盘，每次运行重新输入。** 这是刻意的取舍：光猫的 Telnet 密码
往往是公网可检索的弱口令（如 `Zte521`），把它明文写在 exe 旁边的文本文件里，
等于把「谁能物理接触这台电脑」变成「谁能登录这台光猫」。
多打一次密码的成本远低于这个风险。

设置文件是纯文本可编辑的，想改默认地址直接改即可：

```
# 出于安全考虑，密码不会保存在这里，每次运行需要重新输入。
address=192.168.1.1
port=23
user=root
```

有一条测试专门守着「渲染结果不含密码字段」，防止日后有人手滑加回去。

**2. 换机向导（10 步）**

换光猫是个 20+ 步的流程，之前只能对着教程手动点。现在收进一个分组，
**按 ①～⑩ 编号排列**，照着顺序点即可：

| 步骤 | 内容 |
|---|---|
| ① | 记录原机参数（`setmac show2`、DevInfo、固件版本、硬件信息） |
| ② | 记录原机 WAN 与 VLAN |
| ③ | 记录原机账号表 |
| ④ | 写入 SN（参数化） |
| ⑤ | 写入 PON MAC（参数化） |
| ⑥ | 写入 LOID 宽带识别码（参数化） |
| ⑦ | 劫持 ITMS 注册（防弹注册页） |
| ⑧ | 切断 TR069 远程管理 |
| ⑨ | 保存全部配置 |
| ⑩ | 重启生效 |

①②③ 是**只读的记录步骤**，排在所有写入之前——因为 ④⑤ 会改变设备标识，
不先记下原值就没有回头路。每一步的风险说明里都写明了这一点。

配合 P2-3 的写前备份，④⑤⑥⑧ 执行时还会自动存档被改动的表。

### P2-3：写前备份 + 日志落盘（2026-10-14）

**1. 写操作前自动备份原值**

光猫的 `sendcmd 1 DB set` **立即生效、没有撤销键**，改错了在界面上看不出异常。
所以任何写操作之前，程序会自动把目标表的**原值**抓下来存盘：

```
配置备份/
└─ 20261014 13-48-57_固化 Telnet.txt
```

备份文件是**纯文本、记事本能直接看**（刻意不用 JSON/二进制——
设备出故障时不该还要先写个解析器才能读原值）。内容长这样：

```
# 备份时间: 2026-10-14 13-48-57
# 触发操作: 固化 Telnet
# 涉及表数: 1
===== TelnetCfg =====
<TelnetCfg>
  <Row No="0">
    DM name="TS_Enable" val="0"/>
```

同时原值也会打进日志区——那是你唯一能立刻看到「改之前是什么」的地方。

> 备份失败**不阻断操作**（有些设备会拒绝读某些表），
> 但会在日志里明确写出哪张表没备份成功。
> 只读操作（`p`/`uptime`/`cat` 等）不触发备份。

**2. 操作日志落盘**

内存里的日志到 256KB 就会丢最早的记录，而「改坏了回头查」恰恰依赖最早的记录。
现在每条日志同时追加到 `运行日志/运行日志_<启动时间>.txt`：

- 每次运行一个新文件，便于「昨天那次改坏了」的回溯
- 自动只保留最近 20 个，不会无限堆积
- 启动信息也走同一条落盘路径，保证文件从第一条起就是完整的

### P2-2：参数化表单（2026-10-14）

**改超密、改 SN、改 MAC 这类操作现在有输入表单了**，不用再手打完整命令行。

原先要改个密码得在「自定义命令」里敲 `sendcmd 1 DB set DevAuthInfo 0 Pass 新密码`——
容易敲错字段名，而敲错的后果是静默失败。现在点按钮弹表单，填完点执行。

**新增分组「参数化修改（填表后执行）」**，含 8 个操作：

| 操作 | 参数 | 校验 |
|---|---|---|
| 修改超级管理员账号 | 新账号 | 非空 |
| 修改超级管理员密码 | 新密码 | 至少 8 位，遮蔽显示 |
| 修改普通用户密码 | 新密码 | 至少 8 位，遮蔽显示 |
| 修改 PON MAC | 新 MAC | 12 位十六进制 |
| 修改 SN | SN 前四位 / 后八位 | 4 位 / 8 位字母数字 |
| 修改最大用户数 | 最大用户数 | 十进制整数 |
| 修改 LOID 宽带识别码 | LOID | 非空 |
| 修改 TR069 服务器地址 | 服务器地址 | 非空 |

**在预设文件里声明参数**（想自己加操作的话）：

```text
action 修改超级管理员密码 | danger | 改完请记牢，忘了只能恢复出厂
  param 新密码 | password | 至少 8 位
  cmd sendcmd 1 DB set DevAuthInfo 0 Pass $新密码
  cmd sendcmd 1 DB save
```

可用的校验规则：`text` / `password` / `mac` / `sn4` / `sn8` / `number`。
命令里用 `$参数名` 引用，支持中文参数名。

**三道防线**（都是为了防止「以为改成功了」）：

1. **格式在发到设备之前就校验。** 光猫对 SN/MAC 有硬性格式要求，
   发错了要么静默失败、要么写进一个半吊子值。现在非法输入直接被表单拦住，
   并指出是哪个参数、该怎么改。
2. **危险操作不会因为「填了表单」就跳过确认。** 参数合法后仍然弹二次确认条。
3. **展开后残留 `$` 会被拦下。** 万一模板有问题，程序不会把 `$新密码`
   这种字面量发到设备，而是报错说明。

预设文件写错时（引用了未声明的参数、声明了没用到的参数、参数名重复）
会在启动时报出**具体行号**，不会静默生成一个坏按钮。

### P2-1：预设改为数据驱动（2026-10-14）

**命令清单从 Rust 代码里搬到了 `命令预设.txt`。** 加命令、改字段名现在只需
用记事本编辑文本文件，改完重启程序生效，**不需要重新编译**。

这是为了解决一个必然会发生的问题：中兴光猫的字段名在不同固件/省份版本间
差异很大，改字段名是日常操作，不该每次都走一遍 Rust 工具链。

**文件位置**：exe 同目录下的 `命令预设.txt`。
首次运行时程序会自动生成一份（内容 = 内置清单），直接用记事本编辑即可。

**格式**：

```text
group 状态查看
  action 设备信息
    cmd sendcmd 1 DB p DevInfo
  action 重启光猫 | danger | 重启期间 Telnet 会断开
    cmd reboot
```

- `group <名称>` 开分组
- `action <名称>[ | danger][ | <风险说明>]` 开操作
- `param <名称>[ | <校验规则>][ | <提示文字>]` 声明参数（详见上文 P2-2）
- `cmd <命令原文>` 加命令，一个操作可有多条，按顺序执行
- `#` 开头的整行是注释；缩进仅作可读性，解析时忽略

**三条关键设计**（都为了不让你踩坑）：

1. **文件写坏了会明确报错，不会静默回落。**
   界面上会显示「⚠ 预设文件解析失败」，日志里给出**具体行号**。
   如果静默回落到内置清单，你会以为自己的修改生效了，
   然后去查程序和设备——而真正的问题就在你刚改的那一行。
2. **不覆盖你改过的文件。** 只有文件不存在时才会生成默认清单。
3. **左侧顶部显示「预设来源」**，直接告诉你当前在读哪个文件。
   排查「改了没生效」时第一眼就能看到。

**内置兜底**：exe 内置了一份默认清单（`default_presets.txt`），
所以即使预设文件丢失或被删，程序照样能用。
有一条测试守着「内置清单」与「项目根目录的 `命令预设.txt`」保持同步，
避免改了一份忘另一份。

### 首轮全量审查（2026-10-13）

修复了以下缺陷：

**致命 / 高**
- **程序一启动就崩溃**（`thread 'main' has overflowed its stack`，0xC0000005）。
  根因是 eframe 默认走 wgpu 后端，初始化会耗尽 Windows 给主线程的 1MB 栈。
  已改用 glow 后端并加大主线程栈。**修复前的 exe 完全无法运行。**
- **「固化 Telnet」整条误报超时**：这 7 条 `sendcmd 1 DB set` 都是无输出命令，
  而设备关闭回显时残留提示符 `G7615> ` 会和结束标记粘成一行，整行匹配永远命中不了，
  于是每条都干等满 20 秒并显示「中断：未完成」——而配置其实已经写进去了。
- **`sendcmd 1 DB p` 等表格输出丢首行**：输出首行形如 `<DevInfo>`，
  解析时曾被误当成提示符整行吃掉。
- **提示符漏进输出**：关闭回显时 `G7615> ` 会粘在输出首行前面。

**中**
- 超时后未真正重新对齐 → 上一条命令的迟到输出会污染下一条的结果。
- 连续两条快命令的结束标记可能重复（Windows 时钟分辨率约 15.6ms），
  导致前一条的迟到标记被下一条误判为命中。
- 裸 `IAC SE` 被按三字节解析，吃掉正文一个字节；未分配的 IAC 命令同样会吃正文。
- 填主机名（如 `localhost`）必然失败却报「地址无法解析」；现在支持主机名并依次尝试所有解析地址。
- 设备在超时窗口内断开时被误报成「超时」，导致状态灯不转红、连接对象不丢弃。
- 密码错误时错误信息退化成「与光猫的连接已断开」，用户会去查网络而不是查密码。
- 点「断开」后界面不刷新（egui 事件驱动重绘，`mpsc` 消息不算输入事件），
  状态灯和日志要等用户动一下鼠标才更新。
- worker 线程异常退出后界面仍可点「连接」，会永远停在「连接中...」。
- 大输出时输出匹配是 O(n²)（每个数据包都重扫整块缓冲）。

**低**
- 窄窗口下顶部连接栏会挤出可视区 → 改为可换行布局。
- 未闭合的 IAC 子协商会无限堆积内存；写 socket 未设超时。
- 删除了 `append_log` 里一段不可达的死代码。

## 注意

- 个别命令预设（尤其账号表名）需以你这台 G7615 实际返回为准；
  若某个按钮输出为空或报错，把真实回显记下后微调 `src\presets.rs` 中的命令列表即可。
- 危险操作（重启、改配置）已加二次确认，但仍请执行前确认目标正确。
- 「固化 Telnet」会写入公开的弱口令 `Zte521` 并把关闭时间设成极大值（等于永久开启）。
  仅在自己的局域网内用，用完建议改回强口令或重新关闭 Telnet。
  若字段名与你这台设备不符，`sendcmd 1 DB set` 会静默失败。
  **现在这种情况会被「写后回读校验」抓到并标 ❌**（见上文），
  再用「表结构查询 → 读整表」核对真实字段名即可。

  超时后程序会把该命令的残留输出丢弃并让会话重新对齐，
  所以看到 `[超时]` 说明命令没在 20 秒内跑完，不代表一定失败。
- 日志区上限 256KB，超出后自动丢弃最早的内容，最新输出始终保留。
- 状态灯只在连接真正断开时才变红：执行「重启光猫」后连接会断开，

### P10 · 2026-10-19：第二轮全量审查

逐个模块重读 `telnet` / `dbcli` / `config` / `presets` / `backup` / `settings` / `appearance` /
`paths` / `model` / `ui` / `main`，并对照 egui 0.36 源码核对了 `ScrollArea::show_rows` 与
`Modal` 的行为。本轮 7 处修复全部做了**变异验证**：撤掉修复后对应测试必须失败。

**高**

1. **日志区滚到底时显示的不是最新的行**（`ScrollArea::show_rows` 行高算错）。
   传进去的行高是 `LINE_HEIGHT`（21），而 `.wrap()` 的 Label 单行实际约 16.4px，
   加 `item_spacing` 是 24.4pt。于是滚到底时首行被算成第 ~1300 行，
   那一段被摆到 1300×24.4 ≈ 31700pt，而内容总高只有 30300pt ——
   **日志末尾（`----- 完成 -----`、回读结论）画到了可视区外**，屏幕上留下的是更早的行。
   改为运行时取 `ui.text_style_height(&TextStyle::Monospace)`，与渲染实际行高一致。
2. **未登记的占位命令会原样发到设备**。旧代码只比对 `__SET_TIME_NOW__` 一个字符串，
   预设里写成 `__SETTIME_NOW__`（少一个下划线）或新加占位符忘了接处理逻辑，
   设备回一句 `sh: ...: not found`，界面照样打「----- 完成 -----」。
   现在 `PLACEHOLDERS` 显式登记全集，worker 在 `Run` / `RunRaw` 下发前整批拦截并拒绝，
   提交表单时也拦一次，连上设备后还会扫描清单并提示是哪一条。

**中**

3. **参数校验规则会静默消失**。`parse_param` 用 `i == 1` 判断「第几段是校验规则」，
   于是 `param 新密码 | | password`（多敲一个竖线）把 `password` 当成提示文字收下，
   规则退回默认的 `text` —— 密码长度限制没了，文件解析却显示成功。
   改为「第一个非空段才是规则」。
4. **表格字段可能整行丢失**。既有固件输出 `<Tbl name="X" RowCount="1">` 容器头，
   也有固件把每行写成 `<DM name="X" val="Y"/>`。解析器只认字面量开头 `DM ` 和裸 `<表名>`，
   这些行会被当正文丢掉 —— 回读校验报「未找到字段」，一个其实写成功的操作被判失败。
   现在两种形态都认。
5. **遮蔽串只认半角星号**。部分固件用全角 `＊` 或 `•`/`●` 遮蔽敏感字段；
   少认一种就是「写入其实成功了却报 ❌」的假警报。
6. **备份可能写出被截断的文件**。直接 `std::fs::write` 时，进程在写盘途中被强杀
   会留下半截文本，打开一看像备份、实际后半截没了。改为「写 `.part` → `sync_all` → rename」，
   rename 在同分区是原子的。
7. **闸门的区域码可能被一条假输出满足**。`parse_region` 从整段日志倒找「含 current 的行」，
   用户在「自定义命令」里敲 `echo current 305`，这条 305 就成了「设备读数」，
   「当前区域码必须与设备一致」被绕过。收紧为只认 `current` 打头且紧跟 `=` / `:` 的行。

**顺带改进**

- 闸门的「已备份」改为「已备份（N 张表）」，缺表时在日志里列出缺了哪几张 ——
  只读到 1 张也叫「已备份」，那份文件救不回设备
- 备份完成前，「逐条确认」的三条勾选显式置为弱色并说明现在为什么不能勾
  （`add_enabled_ui` 只关交互，不会自动调暗文字）
- 闸门输入即时校验：填完就提示「两次不一致」，而不是等点了「确认执行」才说
- 回读校验卡片点「清除」改走 worker 通道，避免「清空后立刻又冒出一条旧结论」
  （`ToUi::VerifyCleared`）；每批新写在开始前自动清空上一批
- `Run` 与 `RunRaw` 里重复的两份回读判定逻辑合并为 `verify_after_write`，
  以前两份文案必须字字一致，抄错一处就是两套矛盾的解释
- worker panic 时把 panic 载荷带进 `ToUi::WorkerDead(String)`，悬停状态灯可看到原因
- 参数表单模态补上与另两个模态一致的遮罩不透明度（egui 默认 39%，另两个是 71%）
- 日志裁剪逻辑从 `append_log` 抽成 `trim_log`，终于能被单测直接驱动

### P11 · 2026-10-19：第三轮审查（安全口径与健壮性）

P10 之后又通读了一遍 `main` / `ui` / `config` / `dbcli` / `backup` / `settings` /
`appearance` / `paths`，重点是**两条防线口径是否一致**和**失败路径会不会留下坏状态**。
本轮 7 处修复同样逐条做了变异验证。

**高**

1. **登记了但没独占一条命令的占位符会原样下发**。这是 P10 修复的窄化版本：
   校验按 token 判断「登记过没有」，替换却按「整串相等」判断。于是预设里写
   `date -s __SET_TIME_NOW__`，它能通过校验、又不被替换，字面量就这么发到了设备上。
   现在两处共用同一个判定（`placeholder_of` / `looks_like_placeholder`），
   并且新增 `拦截与展开的口径一致` 这条测试把两个函数钉在一起。
2. **模态开着时仍能发命令**。模态的遮罩只挡鼠标：命令条的输入框照样能编辑，
   `handle_shortcuts` 读的是原始键盘事件。于是区域闸门开着、三项一条没勾的时候
   按 Ctrl+Enter，一条命令就绕过了备份与三段确认 —— 而用户以为自己在闸门里。
   `can_send()` 补上 `!modal_open()`（危险确认 / 参数表单 / 区域闸门三者任一）。

**中**

3. **过期的备份结论会落到新表单上**。点「备份并检查」→ 立刻取消 → 重新打开闸门，
   上一轮的 `CriticalBackupDone` 才到，它把**新表单**填成「已备份（N 张表）」并解锁 ②③，
   而第 ① 步在这次打开里从没执行过。现在 `CriticalBackup` 带一个会话内序号，
   worker 原样回传，对不上（或闸门已关）就丢弃。
4. **参数值只挡换行，不挡 shell 元字符**。表名早有白名单（`is_safe_table_name`），
   理由是「会被拼进命令」；参数值走的是同一条拼装路径，却只拦了 `\r\n`。
   填 SSID 时写 `Home; reboot`，设备会执行两条命令。现在统一拦 `; | & \` $`，
   但放行空格、中文、冒号、斜杠、点号 —— SSID、LOID、服务器地址都要用。
5. **会话日志文件只增不减**。内存日志裁到 256KB，落盘那一份没有上限，
   清理只在下次启动时按个数发生。一次长会话能把单个文件写到几十 MB。
   现在超过 8MB 就轮转一份 `.old.txt`（当前文件从空开始，上一份还能查）。
6. **连接设置与外观设置不是原子写**。`backup.rs` 在 P10 已改成
   「写 `.part` → `sync_all` → rename」，这两个模块还是裸 `write`。
   后果比备份轻（解析宽容、坏文件回落默认值），但「保存过的地址下次启动变回默认」
   同样会让人以为是程序坏了。统一走新增的 `paths::write_atomic`。
7. **日志折行时 `show_rows` 的等高假设不成立**。P10 修的是「行高取错」，
   但 `show_rows` 的根本前提是每行等高，而日志开了 `.wrap()`：一条超长行
   会占两三行，总高度被低估，滚到底时最后几行被画到可视区外。
   现在先估「有没有行会折行」（`line_wraps`，中文按两格算），有就退回整段渲染，
   没有才走虚拟化快路径。

**变异验证**（撤掉修复后对应测试必须失败）

| 修复 | 撤掉后的结果 |
|---|---|
| 占位符口径统一 | `复合命令里的占位符也算未展开` 失败 |
| 模态开时禁发 | `模态开着时不许发命令` 失败 |
| 备份序号比对 | `过期的备份结论被丢弃` 失败 |
| 元字符拦截 | `参数值不接受换行` 失败 |
| 日志轮转阈值 | `日志轮转阈值` 失败（永真/永假都试过） |
| 原子写 | `原子写留下完整文件且不残留临时文件` 失败 |
| 折行判断 | `折行判断按半角宽度估算` 失败 |

> 变异验证的两次自我纠错：① 原子写的第一次变异（改成直接写临时文件）
> 其实仍然会留下 `.part`，测试抓不到，改成「直接写目标文件」才有区分力；
> ② 日志轮转的第一次变异（不先删旧 `.old`）在 Windows 上恰好也能成功，
> 于是把阈值抽成 `should_rotate_log` 单独钉住，改用永真/永假两种变异才抓住。

**测试**：210 → **218**（lib 160 + bin 38 + e2e 20），全部通过。

### P12 · 2026-10-19：常用默认口令菜单

密码框右侧「显示」之后加了一个「常用 ▾」菜单：点开是几条**公开可检索的
出厂默认口令**，选一条就填进输入框。只填、不试、不连、不落盘。

**清单**（顺序即菜单顺序，最可能用到的排前面）

| 账号 / 口令 | 归属 | 出处与可信度 |
|---|---|---|
| `root` / `root` | F650 默认（换 telnetd 后） | 宽带技术网开 telnet 教程 + 恩山免拆机教程，**两条独立来源** |
| `root` / `Zte521` | 中兴 telnet 固件默认 | 两个独立 zteOnu 仓库 README，**已交叉验证** |
| `telecomadmin` / `nE7jA%5m` | 电信超管 / factory | zteOnu 默认认证参数 + 多篇汇总 |
| `CUAdmin` / `CUAdmin` | 联通超管（Web 管理页） | 单来源汇总 |

`root/root` 为什么成立：开 telnet 时把光猫自带的 telnetd 换成了 OpenWrt 子系统里那个，
认证改读 `/opt/upt/framework/saf/rootfs/etc/shadow`，不再受 `TelnetCfg` 表控制 ——
所以在表里写 `Zte521` 对这种情况无效。这解释了为什么「固化 Telnet」写了 `Zte521`、
实际登录却要用 `root/root`。

**没收录的**：`admin/admin`、`root/admin` 这类论坛里口口相传但查不到一手出处的组合。
收进来就是拿用户的设备去试，不如不写。移动 `CMCCAdmin/aDm8H%MdA` 也没放 ——
它是移动 Web 超管，与本程序的 telnet 场景无关，混进来会让菜单看起来像「什么都试试」。

**填充规则**（两条，都有测试钉住）

1. **口令总是覆盖** —— 点它就是为了换口令
2. **账号只在为空时填** —— 用户自己敲的账号优先；否则点一下 `telecomadmin`
   就把辛苦敲的 `root` 冲掉了，而界面上看不出「它替我改了账号」

不做「顺便帮你连一下」：连不连是用户的决定，自动连接会把「填错口令被设备拒绝」
变成一次莫名其妙的失败弹窗。

**与「密码不落盘」红线的关系**

红线针对的是**用户自己改过的密码**。清单里是厂商出厂值，本来就印在别人的论坛帖
和开源工具 README 里，写进源码不泄露任何东西。两件事不能混为一谈：
把 `Zte521` 写进源码没有风险，把用户自己设的密码写进源码才是事故。

为此新增一条测试 `预设口令不会被写进连接设置`：断言 `数据/连接设置.txt` 的
**键集合只能是 address / port / user 三项**。

> 这条测试第一版写错了：原本断言 `!text.contains(p.password)`，
> 但默认账号恰好是 `root`，而 `root/root` 那条的口令也是 `root`，
> 于是 `user=root` 这一行让断言假失败。改成断言键集合 + 逐项比对值才有意义。

**测试**：218 → **225**（lib 165 + bin 40 + e2e 20），全部通过。
新增：`预设口令清单合法`、`F650默认口令在清单首位`、`选中预设时的填充规则`、
`菜单文字包含账号口令与归属`、`预设口令不会被写进连接设置`、
`带常用菜单时密码标签仍居中`、`最小窗口宽度下顶栏放得下`。

| 变异 | 应失败的测试 | 结果 |
