## 1. 借鉴了谁、借鉴了什么

参考对象的取值为调研时各站公开的设计资料，落到本项目时**按第 3 节的令牌重新取值**，
不照搬原始色值（原始值多为网页场景，与 egui 的线性色空间和暗色面板层次不同）。

| 参考对象 | 借鉴点 | 换算到本项目 |
|---|---|---|
| **Linear** | 暗色层次靠 **surface 明度差**而不是投影堆叠；1px 弱边框做容器分界；高信息密度、低装饰 | 三级 surface：`#0E1116` → `#151A21` → `#1C232C`，相邻层亮度差约 5–7 点，不用大阴影；所有卡片/面板统一 1px `#2A333F` 描边 |
| **Vercel Geist** | 单一强调色 + 严格的间距刻度；状态用低饱和底色标签而不是大面积色块 | 强调色只保留 `#4CC2FF` 一支；间距刻度斐波那契化（2/4/8/13/21/34/55/89）；危险/成功用 15% 透明度底色 + 同色文字 |
| **GitHub Primer (dark)** | 语义色板 success / danger / attention / info 的四分法；`*-muted` 语义底色 | 直接对应回读校验三态：success `#3FB950`、danger `#F85149`、attention(warning) `#D29922`、info `#58A6FF`；底色 `#0F2417` / `#2D1417` |
| **Raycast** | 命令面板式**整行可点**列表、紧凑行高、快捷键提示用弱色小字靠右；近黑背景带冷蓝倾向 | 左侧操作列表改成整行按钮（高 34），行尾危险徽标右对齐；背景 `#0E1116` 带蓝调而非纯黑；快捷键提示用 12px 弱文字 |
| **shadcn/ui** | 卡片 = 圆角 + 1px 边框 + 无投影；分隔线只在必要处出现 | 卡片圆角 13、边框 1px `#2A333F`、无阴影；分组之间用 21 间距 + 1px 分隔线，取消满屏 `ui.separator()` |
| **UniFi / OpenWrt LuCI** | 设备管理面板的信息层级：**状态优先、操作为次**；连接状态永远在最显眼处 | 顶栏左侧固定状态灯 + 连接胶囊；操作按钮一律降级到侧栏，不与状态争视觉权重 |

**明确不借鉴**：Linear/Raycast 的营销页大标题与渐变、UniFi 的图表化仪表盘 ——
本程序是单窗口工具，一屏内要放下 55 个操作，装饰性元素一律不做。

## 2. 间距刻度（斐波那契，比值趋近 φ）

```
2, 4, 8, 13, 21, 34, 55, 89
```

相邻项比值：2.0 / 2.0 / 1.625 / 1.615 / 1.619 / 1.618 / 1.618 —— 从第 3 项起收敛到 φ。

| 令牌 | 值 | 用途 |
|---|---|---|
| `SPACE_2` | 2 | 徽标内边距、图标与文字的最小间隙 |
| `SPACE_4` | 4 | 控件内部微调 |
| `SPACE_8` | 8 | 控件内边距、行内元素间距（默认 `item_spacing`） |
| `SPACE_13` | 13 | 卡片内边距、列表项左右留白 |
| `SPACE_21` | 21 | 分组间距、区块之间的呼吸 |
| `SPACE_34` | 34 | 大区块间距、顶栏内边距 |
| `SPACE_55` | 55 | 顶栏高度、面板级留白 |
| `SPACE_89` | 89 | 空状态居中区域的留白 |

**规则**：布局代码里除 `0.0` 外不允许出现刻度以外的数字（第 5 节有自查命令）。

## 5. 无障碍：实测对比度

按 WCAG 2.1 相对亮度公式计算（`L = 0.2126R + 0.7152G + 0.0722B`，各通道先做 sRGB 线性化），
对比度 = `(L_light + 0.05) / (L_dark + 0.05)`。背景取最暗的 `BG_BASE` `#0E1116`（最不利情况）。

| 前景 | 对 `#0E1116` | 对 `#151A21` | 对 `#1C232C` | 要求 | 结论 |
|---|---|---|---|---|---|
| `TEXT_PRIMARY` `#E6EDF3` | **16.00 : 1** | 14.79 : 1 | 13.40 : 1 | ≥ 4.5 | ✅ 通过 |
| `TEXT_SECONDARY` `#9BA9B8` | **7.89 : 1** | 7.29 : 1 | 6.61 : 1 | ≥ 4.5 | ✅ 通过 |
| `TEXT_MUTED` `#6B7A8C` | **4.31 : 1** | 3.98 : 1 | 3.61 : 1 | ≥ 3.0 | ✅ 通过（仅用于非正文的提示文字） |
| `ACCENT` `#4CC2FF` | 9.43 : 1 | 8.71 : 1 | 7.89 : 1 | ≥ 4.5 | ✅ 通过 |
| `SUCCESS` `#3FB950` | 7.44 : 1 | 6.88 : 1 | 6.23 : 1 | ≥ 4.5 | ✅ 通过 |
| `DANGER` `#F85149` | 5.64 : 1 | 5.21 : 1 | 4.72 : 1 | ≥ 4.5 | ✅ 通过 |
| `WARNING` `#D29922` | 7.49 : 1 | 6.92 : 1 | 6.27 : 1 | ≥ 4.5 | ✅ 通过 |

（上表数值由 `src/theme.rs` 的 `contrast_ratio` 单元测试同公式复算，
测试会断言：正文 ≥ 4.5、次要 ≥ 4.5、弱文字 ≥ 3.0。改色板时测试会先炸。）

**三态校验不依赖颜色**：✅ / ❌ / ⚠ 三种**形状**不同，色盲用户也能区分。

### 截图是怎么拍的

本机当前处于锁屏状态（`LogonUI` 在运行），GDI `CopyFromScreen` 只能拿到锁屏壁纸。
所以程序内置了只服务于验收的 `--screenshot` 模式，走 `ViewportCommand::Screenshot`
取渲染结果本身，与屏幕是否可见无关；配套参数 `--width` / `--sidebar` / `--open-groups` / `--demo`
也只在这个模式下有意义。正常双击运行完全不经过这些分支。

## 11. v1.1 双主题与连接区标签化（2026-10-18）

### 11.1 主题系统

- **支持浅色 / 深色 / 跟随系统**三种模式，默认**跟随系统**
  - 默认值从「浅色」改成「跟随系统」：系统的浅深偏好是用户早已设好的，
    程序再猜一次「你要浅色」只会在夜间白得刺眼
  - 「跟随系统」探测不到时的兜底仍是**浅色**（`fallback_theme = Light`），不是 egui 默认的深色
- 外观设置存于 `数据\外观设置.txt`，格式 `theme=light|dark|system`，损坏时回落默认（跟随系统）
- 两套 `Visuals` 分别安装：`set_visuals_of(Theme::Dark, ...)` + `set_visuals_of(Theme::Light, ...)`
  - **禁止**用 `ctx.set_visuals()` —— 只写当前主题，切换后配色丢失
- 浅色 `Visuals` 从 `Visuals::light()` 派生（字体渲染伽马不同），不是从 `dark()` 改色

### 11.3 连接区标签化

- 顶栏改为**两段式**：第 1 行 = 品牌 + 机型 + 状态 + 外观菜单；第 2 行 = 四个「上标签下输入」字段组
- 标签文字：`光猫 IP`、`端口`、`Telnet 账号`、`Telnet 密码`
- 默认值 `192.168.1.1 / 23 / root` 是**真实字符串**预填，不是 placeholder
- 密码框 hint 写 `不保存，每次运行需重填`（示例提示，非替代标签）
- 端口框固定窄宽 55px（够 65535 五位）
- 输入框里的**文字**也必须在框内水平 + 垂直居中
  - egui 的 `TextEdit` 默认是 `Align2::LEFT_TOP`，不显式设置文字会贴左上角
  - 截图实测修复前靠左 8.5~40px、靠上 11px；修复后偏差 ≤ 2px
  - 统一由 `theme::centered_edit` 构造，顶栏四个框与区域闸门三个框共用
  - 回归测试 `输入框里的文字居中` 从绘制指令读文字墨迹矩形并与框中心比对
- 四个标签必须**各自居中在自己的输入框正上方**（误差 ≤ 1px，实测 -1 ~ -1.5px 为抗锯齿）
  - `add_sized` 内部是 `Layout::centered_and_justified`，宽度传多少文字就居中到多少
  - 密码框**不能**把标签宽度传成「输入框 + 间隙 + 显示按钮」：那样标签会右移半个按钮宽
  - 由 `theme::label_above` 统一处理，两个调用点都只传输入框自身宽度
  - 回归测试 `每个标签都居中在自己输入框正上方` 会跑真实 egui 布局并从绘制指令读文字位置
- 顶栏高度 `TOPBAR_HEIGHT` 由 55 提到 **102**（= `SPACE_89 + SPACE_13`，两个刻度项相加）
  - 需求原文写的是 89，但两段式实际占位是 16+21+8+57 = 102，取 89 会被裁切
  - 面板高度用 `set_height` 锁死（min 与 max 都设），防止子布局把它撑开

### 11.4 区域修改闸门

- 新增 `critical` 关键字（比 `danger` 高一级），解析为 `danger=true` 且 `critical=true`
- 新增 `Route::Critical`，走专用模态：**备份 → 三勾选 → 双输入 → 执行**
- 「备份」必须是**真的备份**：由专用消息 `ToWorker::CriticalBackup` 先
  `sendcmd 1 DB p` 出 8 张关键表的原值再写盘，**读不到原值就不解锁第 ②③ 步**
  - 早期实现只把「即将执行什么」写进备份文件，等于没备份
  - 也不能复用 `ToWorker::Run`：它的备份只对 `sendcmd 1 DB set` 推导表名，
    纯 `cat` 命令推导为空会直接跳过备份，且备份失败不阻断
- 预设新增：
  ```
  action 修改区域码 | critical | 会立即重启；配置重置为该省默认模板...
    param 目标区域码 | region | 三位数字，先点「查看区域代码表」确认
    cmd upgradetest sdefconf $目标区域码
  ```
- `ParamKind::Region` 要求三位数字，写错直接拦截


### 11.5 闸门的反馈真实性（2026-10-19）

闸门的存在意义是「不可逆操作之前必须让人看清代价」。只把按钮做成禁用、
却不说清**为什么不能点**、**备份覆盖了什么**，等于把判断全推给用户。

- 「已备份」改为 **「已备份（N 张表）」**；缺表时在日志里列出缺了哪几张 ——
  只读到 1 张也叫「已备份」，那份文件救不回设备
- 备份完成前三勾选显式置为 `text_muted`，并写明「完成第 ① 步后才能勾选」。
  注意 `add_enabled_ui` 只关**交互**，不会自动调暗文字，看起来和可用时一模一样
- 输入即时校验：填完就提示「两次输入的目标区域码不一致」，不等点了「确认执行」才说
- 遮罩不透明度统一为 `MODAL_BACKDROP_ALPHA`（180/255），三个模态一致；
  egui 的 `Modal` 默认是 `from_black_alpha(100)`（39%），深浅不一会让人觉得「没画完」

### 11.6 日志视图的行高（2026-10-19）

`ScrollArea::show_rows` 只画 `[首行, 末行]` 这一段，并把它**整体摆到第 min_row 行的位置**。
所以传进去的行高必须等于渲染时的实际行高，否则：

- 传得比实际行高大 → 首行索引被算得偏后，那一段被整体摆到内容总高之外，
  **末几行画在可视区外**（本项目实测：`LINE_HEIGHT` 21 + 间距 8 = 29pt，
  而 `.wrap()` 的 Label 单行约 16.4pt + 间距 8 = 24.4pt；滚动到底时
  末行被摆到比内容总高还低约 1400pt 的位置，屏幕上留下的是更早的行）
- 正确做法：`ui.text_style_height(&egui::TextStyle::Monospace)`，运行时取真实行高

但**行高取对只是必要条件**：`show_rows` 的根本前提是「每行等高」，
而日志开了 `.wrap()`。一条超长行（某个字段的 `val` 特别长）会占两三行，
整段高度被低估，滚到底时最后几行照样被画到可视区外。

所以渲染前先估一遍「有没有行会折行」（`line_wraps`，中文按两格算，宁可判宽）：

- 没有折行 → 走 `show_rows` 虚拟化快路径（日志上限 256KB，全量排版会掉帧）
- 有折行 → 退回 `show()` 整段渲染，排版精确，代价可以接受

### 11.7 阻断性模态必须同时关掉键盘路径（2026-10-19）

`egui::Modal` 的遮罩只挡**鼠标**：它把底层控件的点击拦掉了，但
`Context::input` 里的原始键盘事件照旧可读。本项目的命令条还有两处绕过点：

- 输入框本身没被禁用，仍可编辑
- `handle_shortcuts` 直接读 `consume_key(CTRL, Enter)`，不经过任何控件

后果不是「多一条命令」：区域闸门开着、三项一条没勾的时候按 Ctrl+Enter，
命令就绕过备份与三段确认发了出去，而用户以为自己在闸门里。

规则：**`can_send()` 必须包含 `!modal_open()`**（危险确认 / 参数表单 / 区域闸门三者任一）。
侧栏按钮、命令条、快捷键共用同一个判定，不允许各自再写一份条件。

### 11.8 一次操作的回执必须能对上「这一次」（2026-10-19）

区域闸门的第 ① 步是异步的：界面发 `CriticalBackup`，worker 跑完回 `CriticalBackupDone`。
而闸门可以被「取消」关掉再重新打开 —— 此时上一轮的回执才到，
它会把**新表单**填成「已备份」并解锁第 ②③ 步，而这次打开里一次备份都没跑过。

规则：异步回执必须带一个**会话内单调递增的序号**，界面收到时比对当前表单的序号，
对不上（或表单已经关掉）就丢弃。不要用「有没有收到回执」当状态，
那只能说明「曾经有人发起过」。
### 11.9 常用口令菜单的填充规则（2026-10-19）

密码框右侧的「常用 ▾」是**填入辅助**，不是「尝试登录」：只把公开的出厂默认口令
写进输入框，不自动连接、不批量试错。

- **口令总是覆盖**：点它就是为了换口令
- **账号只在为空时填**：用户自己敲的账号优先。否则点一下 `telecomadmin`
  就把 `root` 冲掉了，而界面上看不出「它替我改了账号」
- 全空白视为空（用户可能敲了个空格）

菜单项文字统一为 `账号 / 口令 · 归属`，悬停补一句「不是本机保存的密码」——
避免用户以为程序记住了他的密码。
